# TextMorph for SwiftUI: working notes

A SwiftUI port of the web library [Torph](https://torph.lochie.me)
(MIT, copyright 2025 Lochie Axon). Its twin is
[textmorph-android](https://github.com/dim971/textmorph-android); the two are
kept in step deliberately.

Upstream has one public component, `<TextMorph />`. The 33 entries on its
examples page are demos built with it, not components of it. This port has one
public view for the same reason.

## The one rule that matters

**The engine's output is pinned to the JavaScript original.**

`Tests/TextMorphTests/Fixtures/goldens.json` is generated from the published
npm package by `Tools/gen-goldens.mjs`. The tests rebuild each case through the
Swift engine and compare. There is no tolerance and there is not meant to be
one.

If a golden fails, the port has drifted. Find out why. Do not widen anything,
do not regenerate the fixtures to make a failure go away. Regenerating is only
correct when deliberately tracking a new upstream version, and the diff should
be explainable.

## Deliberate deviations from upstream

Three, all forced, all with their own fixture section marked as deviating. They
are listed in full in `docs/fidelity.md`.

- **Minted numeric ids.** Upstream mints them from a module-global counter,
  which is unusable under Swift 6 strict concurrency and is not reproducible
  even in JavaScript, since the counter climbs for the life of the process. The
  port passes a `MintedIds` instance, owned by the view's engine. Upstream only
  requires uniqueness against the ids already in play, so the behaviour is the
  same. Fixtures canonicalise any id starting with U+0000 to `#0`, `#1` and so
  on, in order of first appearance.
- **Character splitting.** Upstream uses `String.prototype.split("")`, which
  cuts on UTF-16 code units and therefore halves an astral character into two
  surrogates. Swift cannot hold an unpaired surrogate. The port splits on
  extended grapheme clusters. This changes ids and the character diff only for
  words containing an astral character.
- **Critical damping.** Upstream's spring is analytic, and at a damping ratio
  of exactly 1 its overdamped branch divides by zero: `springPosition` returns
  NaN, and because `NaN > precision` is false, `computeDuration` concludes the
  spring settled at t = 0 and returns a duration of `-0` ms. The port adds the
  analytic critical branch. Deviating identically on both platforms is the
  requirement; following upstream here would ship a broken option.

Everything else stays on UTF-16 offsets: `space-{index}`, `newline-{offset}`,
the `charOffset` walk in the diff, and the public `cursorIndex`. `Core` accepts
no `String.Index` anywhere for this reason. It is the most likely silent parity
break in the whole port.

## What the rendering probe established

Measured, not assumed, before any of this was written. `docs/architecture.md`
carries the numbers.

- **Splitting the value into segments costs nothing.** Drawing one glyph run
  per segment, taking glyphs, advances and positions out of the runs of the
  whole-line `CTLine`, is identical to a single `CTLineDraw` of the whole value.
  Zero differing pixels at every system text style.
- **It is also identical to SwiftUI `Text`.** Once both sides are pinned to the
  same fill colour and the baseline is inside the plateau near the line's
  ascent, the canvas draw and `Text` agree pixel for pixel at every system
  style. The apparent difference before that is `labelColor`, which is not
  opaque.
- **Measuring segments in isolation does not work.** Summing per-character
  advances drifts: `"AVATAR Wave"` gains 11.29pt on 157pt at 26pt, and 21.09pt
  on 287pt at 48pt. The error accumulates. Cumulative prefixes stay under
  1.7pt and land exactly on the whole-line width, so they are a usable
  fallback; isolated advances are not.
- The system font does not form fi or fl ligatures under CoreText's defaults,
  and neither do Times, Georgia or Menlo, so a segment boundary inside a
  ligature is not a live problem on this platform. It is on Android, and the
  twin disables the ligature features to match.

## Layout

```
Sources/TextMorph/
  Core/      pure logic, no UI type in any signature. Segmentation, the diff,
             number place alignment, the spring, the bezier, the morph plan.
  Engine/    text shaping, the layout cache, the clock, the state machine.
  Views/     the public TextMorph view, its options, the canvas.
Tests/       goldens, plan samples, layout drift, interruption
Showcase/    the catalog app (project generated by XcodeGen, not checked in)
Tools/       gen-unicode-tables.mjs, gen-goldens.mjs, gen-plan-goldens.mjs,
             gen-icon.mjs: Node, run by hand
```

`docs/architecture.md` explains how a value reaches the screen.

## Conventions worth keeping

- **Zero warnings.** Package and showcase, on the release Xcode *and* the
  current beta. Check both with `DEVELOPER_DIR`.
- **One linear clock.** The platform supplies elapsed time and nothing else.
  Every curve is applied by us. Upstream animates transforms with the author's
  easing and opacity linearly over a fraction of the duration; if the clock
  itself were eased, recovering linear time would need the curve's inverse and
  every fade window would be wrong.
- **Segmentation lives in `Core`.** UAX #29 rules over generated tables, not
  the platform's ICU. Foundation and Android's ICU disagree with each other and
  with `Intl.Segmenter`, and Foundation is not even self-consistent about
  spaces once a CJK character appears. Using each platform's ICU would
  guarantee a divergence rather than avoid one.
- **`UnicodeBreakTables.swift` is generated.** Never edit it by hand. It is
  excluded from SwiftLint for that reason.
- **Positions and glyphs come from the same shaping.** Mixing two sources of
  truth is how the Android twin lost 2.35px on a tracked value.
- Comments explain why, not what. If a constant looks arbitrary, say where it
  came from.
- **No em dash (U+2014), and no en dash (U+2013).** Not in code, comments,
  docs, commit messages or issue and pull request text. Use a comma, a colon, a
  semicolon, parentheses or a full stop. CI fails the build if either character
  reappears.

## Verifying

```sh
make test                                  # goldens
make lint                                  # swiftformat --lint, swiftlint
make showcase                              # build and run in the simulator
DEVELOPER_DIR=/Applications/Xcode-<beta>.app/Contents/Developer swift build --build-tests
```

Screenshots: `xcrun simctl io booted screenshot out.png`. A morph is a
transition, so a still frame proves little; prefer
`xcrun simctl io booted recordVideo out.mov`, or assert on
`MorphPlan.frame(atElapsed:)`, which is pure.

## Staying in step with Android

A change to shared behaviour (segmentation, the diff, number alignment, the
timing of a morph, the shape of `MorphPlan`) should land in both repositories.
The Kotlin port mirrors `Core` file for file, `Tools/` is byte identical, and
both replay the same `goldens.json` and `plan-goldens.json`.
